## 頁面與介面清單

### 頁面 1 — 橫幅廣告列表頁
- **路由**：`/admin/banners`
- **存取權限**：ROLE_ADMIN
- **UI 元件**：
  - 頁面標題「橫幅廣告管理」
  - 篩選列（狀態下拉選單：全部 / 已發布 / 未發布、關鍵字搜尋）
  - 「新增廣告」按鈕（右上角，Primary）
  - 資料表格：
    - 欄位：縮圖、關聯店家名稱、顯示順序、狀態徽章、排程時間、操作按鈕群
    - 狀態徽章：已發布（綠）、未發布（灰）、排程中（藍）
    - 操作按鈕：編輯、發布／取消發布、上移／下移、刪除
  - 空狀態提示：「尚無任何廣告，請點擊「新增廣告」建立第一筆廣告。」

### 頁面 2 — 新增廣告 Modal
- **路由**：`/admin/banners`（Modal 覆蓋）
- **存取權限**：ROLE_ADMIN
- **UI 元件**：
  - Modal 標題「新增橫幅廣告」
  - 圖片上傳區（拖曳或點擊選取，支援 JPG/PNG/WebP，最大 5MB，顯示預覽）
  - 關聯店家選擇器（下拉搜尋，資料來自 `/api/admin/stores`）
  - 顯示順序數字輸入（最小值 1）
  - 排程設定區塊（可選）：
    - 發布時間（DateTimePicker）
    - 下架時間（DateTimePicker）
  - 狀態切換（預設：未發布）
  - 確認／取消按鈕

### 頁面 3 — 編輯廣告 Modal
- **路由**：`/admin/banners`（Modal 覆蓋）
- **存取權限**：ROLE_ADMIN
- **UI 元件**：
  - 同新增 Modal，標題改為「編輯橫幅廣告」
  - 預填所有現有資料
  - 現有圖片預覽 + 重新上傳選項

### 頁面 4 — 顯示順序管理（拖曳排序）
- **路由**：`/admin/banners/reorder`（或同列表頁 inline）
- **存取權限**：ROLE_ADMIN

  - 拖曳排序列表（drag handle icon）
  - 「儲存順序」按鈕
  - 即時預覽排序結果

## 使用者情境與測試

### 使用者故事 1 — 管理員新增一則橫幅廣告並立即發布（優先級：P1）

管理員進入廣告列表頁，點擊「新增廣告」，填寫圖片、選擇關聯店家並設定顯示順序，儲存後手動點擊「發布」使廣告在前台輪播中顯示。

**此優先級的原因**：這是橫幅廣告的核心功能，必須在任何其他功能之前完成並可用。

**獨立測試**：確保後端有至少一間狀態為 enabled 的店家，上傳一張測試圖片，完成新增流程。

**驗收情境**：
1. **在** 廣告列表為空的狀態下，**當** 管理員填寫完整表單並點擊「儲存」，**則** 廣告以「未發布」狀態出現在列表頁第一列。
2. **在** 廣告處於「未發布」狀態，**當** 管理員點擊「發布」，**則** 狀態徽章變為「已發布（綠色）」，並在前台首頁輪播中可見。
3. **在** 新增表單未選擇關聯店家，**當** 點擊「儲存」，**則** 顯示驗證錯誤「請選擇關聯店家」，不送出 API。

---

### 使用者故事 2 — 管理員設定排程廣告（優先級：P1）

管理員希望廣告在特定時間自動上架、下架，減少手動操作。

**此優先級的原因**：排程功能是廣告管理的核心差異功能，確保活動廣告準時顯示。

**獨立測試**：設定發布時間為「現在 + 2 分鐘」，等待並確認狀態自動切換。

**驗收情境**：
1. **在** 新增廣告表單中，**當** 管理員設定發布時間為未來時間並儲存，**則** 廣告狀態顯示「排程中（藍色）」及預計發布時間。
2. **在** 已發布廣告設有下架時間，**當** 下架時間到達後（後端自動執行），**則** 廣告狀態自動變為「已下架」，前台不再顯示。
3. **在** 設定排程時間，**當** 發布時間晚於下架時間，**則** 表單驗證提示「下架時間必須晚於發布時間」。

---

### 使用者故事 3 — 管理員調整廣告顯示順序（優先級：P2）

多筆廣告存在時，管理員需要控制前台輪播的顯示順序。

**此優先級的原因**：顯示順序影響廣告曝光優先級，但不阻礙基本功能使用。

**獨立測試**：建立至少 3 筆廣告，透過上移／下移按鈕調整順序，確認後台列表與前台輪播均反映變更。

**驗收情境**：
1. **在** 廣告列表有 3 筆以上廣告，**當** 管理員對第二筆廣告點擊「上移」，**則** 該廣告與第一筆交換位置，並立即在列表中反映。
2. **在** 管理員完成排序調整，**當** 點擊「儲存順序」，**則** 顯示「順序已更新」成功提示，前台輪播按新順序播放。

---

### 使用者故事 4 — 管理員取消發布並刪除廣告（優先級：P2）

管理員需要下架過期廣告並清理資料。

**此優先級的原因**：資料維護功能，不影響核心流程但需要正確實作。

**驗收情境**：
1. **在** 廣告處於「已發布」狀態，**當** 管理員點擊「取消發布」，**則** 狀態變為「未發布」，前台不再顯示。
2. **在** 廣告處於「未發布」狀態，**當** 管理員點擊「刪除」並確認，**則** 廣告從列表移除。
3. **在** 廣告處於「已發布」狀態，**當** 管理員嘗試直接刪除，**則** 系統提示「請先取消發布再刪除」。

---

### 邊界情況

- 上傳圖片超過 5MB 時，顯示「圖片大小不得超過 5MB」錯誤，不進行上傳。
- 關聯店家被停用後，已發布廣告應顯示警告徽章「關聯店家已停用，前台不顯示」。
- 顯示順序輸入非整數或小於 1 時，驗證錯誤。
- 網路請求失敗時，顯示 Toast 錯誤訊息並保留表單內容。
- 空圖片 URL 不應顯示損壞圖示，改顯示佔位圖。

## API 串接規格

### 廣告管理

| 動作 | Method | 端點 | 主要 Request 欄位 | 主要 Response 欄位 | 前端 UI 狀態 |
|------|--------|------|------------------|--------------------|-------------|
| 取得廣告列表 | GET | `/api/admin/banners` | — | `[{id, storeId, storeName, imageUrl, displayOrder, status, publishTime, unpublishTime}]` | loading spinner → 表格渲染 |
| 新增廣告 | POST | `/api/admin/banners` | `imageUrl, storeId, displayOrder, status, publishTime, unpublishTime` | `{id, storeId, storeName, imageUrl, displayOrder, status}` | 按鈕 loading → 成功 Toast → Modal 關閉 |
| 更新廣告 | PUT | `/api/admin/banners/{id}` | `imageUrl, storeId, displayOrder, status, publishTime, unpublishTime` | `{id, ...更新後資料}` | 按鈕 loading → 成功 Toast → Modal 關閉 |
| 刪除廣告 | DELETE | `/api/admin/banners/{id}` | — | `{success: true}` | 確認 Dialog → loading → 列表移除 |
| 發布廣告 | POST | `/api/admin/banners/{id}/publish` | — | `{id, status: "PUBLISHED"}` | 按鈕 loading → 狀態徽章更新 |
| 取消發布廣告 | POST | `/api/admin/banners/{id}/unpublish` | — | `{id, status: "UNPUBLISHED"}` | 按鈕 loading → 狀態徽章更新 |
| 取得店家選單 | GET | `/api/admin/stores` | — | `[{id, name}]` | 下拉選單 loading |

## 功能需求（前端 UI）

### 介面需求

- **FR-UI-001**：廣告列表頁以表格呈現，包含縮圖欄（固定尺寸 80×45px）、店家名稱、顯示順序（數字）、狀態徽章、排程時間（若無排程顯示「—」）、操作按鈕群。
- **FR-UI-002**：狀態徽章三種樣式：已發布（綠底白字）、未發布（灰底深灰字）、排程中（藍底白字）。
- **FR-UI-003**：新增／編輯 Modal 需包含圖片上傳預覽，未上傳前顯示佔位符虛線框。
- **FR-UI-004**：關聯店家選擇器需支援文字搜尋篩選（前端 filter 或後端搜尋）。
- **FR-UI-005**：排程時間 DateTimePicker 需支援清除（可選欄位）。
- **FR-UI-006**：上移／下移按鈕：第一筆廣告「上移」按鈕 disabled，最後一筆「下移」按鈕 disabled。
- **FR-UI-007**：刪除操作需二次確認 Dialog：「確定要刪除此廣告？此操作無法復原。」
- **FR-UI-008**：列表頁支援依狀態篩選（全部、已發布、未發布、排程中）。
- **FR-UI-009**：廣告圖片縮圖點擊後彈出大圖預覽 Modal。
- **FR-UI-010**：關聯店家被停用時，該廣告列表列顯示警告 icon 並 tooltip 說明。

### 狀態管理

- **SM-001**：列表初始載入時顯示 skeleton loading，資料載入後渲染表格。
- **SM-002**：所有 API 請求失敗時，顯示右下角紅色 Toast 錯誤訊息，保留頁面現有狀態。
- **SM-003**：新增／編輯成功後，顯示綠色 Toast「廣告已成功儲存」，關閉 Modal，重新載入列表。
- **SM-004**：發布／取消發布成功後，即時更新該列狀態徽章，無需重新載入整頁。
- **SM-005**：表單提交時，按鈕切換為 loading 狀態並 disabled，防止重複提交。
- **SM-006**：圖片上傳進行中顯示進度條，完成後顯示預覽圖。

## API 驗證清單

- **AV-001** ✅：`GET /api/admin/banners` 回傳 `storeName` — 列表頁可直接顯示店家名稱，無需額外查詢。
- **AV-002** ✅：`status` 欄位回傳值（`PUBLISHED`/`UNPUBLISHED`）— 與前端徽章對應明確。
- **AV-003** ⚠️：排程狀態（`SCHEDULED`）— 後端 spec 未明確定義 status 是否有第三值，或以 `publishTime` 存在且未來為判斷依據；前端需與後端確認 status 的可能值列表。
- **AV-004** ⚠️：圖片上傳端點 — 後端 spec 提供 `imageUrl` 欄位，但未說明圖片如何上傳（直接 POST 還是先上傳 S3 取得 URL）；需確認上傳流程。
- **AV-005** ❌：`GET /api/admin/banners` 無排序或分頁參數 — 廣告數量增多後可能影響效能；建議確認後端是否支援分頁。
- **AV-006** ⚠️：顯示順序批次更新 — 後端僅提供 `PUT /api/admin/banners/{id}` 逐一更新，若需拖曳排序批次儲存，需要批次更新 API 或逐一呼叫；需確認是否有 bulk update 端點。
- **AV-007** ✅：`GET /api/admin/stores` 提供店家下拉選項 — 資料來源確認可用。
- **AV-008** ⚠️：店家停用狀態 — `GET /api/admin/banners` 回應中未包含關聯店家的 `storeStatus` 欄位；前端無法直接判斷店家是否已停用，需額外呼叫或後端加入此欄位。
- **AV-009** ❌：刪除已發布廣告的後端防護 — 後端 spec 未說明是否限制刪除已發布廣告；前端需實作前置判斷，若狀態為已發布則顯示「請先取消發布」提示而非呼叫 DELETE API。

凡例：✅ 已確認一致 | ⚠️ 需要確認 | ❌ 發現缺口或不一致

## 成功標準

### 可量化的成果

- **SC-001**：管理員可在 3 步驟內（點擊新增 → 填寫表單 → 儲存）完成一筆廣告建立。
- **SC-002**：廣告列表頁在 100 筆資料以內，載入時間不超過 2 秒。
- **SC-003**：圖片上傳 5MB 以內的檔案，完成上傳並顯示預覽在 5 秒內。
- **SC-004**：發布／取消發布操作後，狀態即時更新（不需手動重新整理頁面）。
- **SC-005**：所有表單驗證錯誤訊息在使用者離開欄位（onBlur）後立即顯示。
- **SC-006**：排程時間設定後，列表頁正確顯示預計發布／下架時間（格式：YYYY-MM-DD HH:mm）。
