# 前端規格書（後台）：最新消息管理

**功能分支**：`007-news-management`
**對應後端 Spec**：`specs/007-news-management/spec.md`
**建立日期**：2026-03-27
**狀態**：草稿
**介面類型**：後台管理介面（Admin Panel）
**存取角色**：ROLE_ADMIN

---

## 頁面與介面清單

### 頁面 1 — 消息列表頁
- **路由**：`/admin/news`
- **存取權限**：ROLE_ADMIN
- **UI 元件**：
  - 頁面標題「最新消息管理」
  - 篩選列：
    - 類別下拉（全部 / 公告 ANNOUNCEMENT / 活動 EVENT / 系統 SYSTEM）
    - 重要性篩選（全部 / 重要消息）
    - 關鍵字搜尋（標題關鍵字）
    - 日期範圍選擇器（發布時間）
  - 「新增消息」按鈕（右上角，Primary）
  - 資料表格：
    - 欄位：縮圖（若有）、標題、類別徽章、重要標記（⭐）、狀態徽章、排程時間、操作
    - 狀態徽章：草稿（灰）、已發布（綠）、已封存（橘）、排程中（藍）
    - 操作：編輯、發布／取消發布、封存、刪除
  - 空狀態提示

### 頁面 2 — 新增消息頁面（全頁或側邊 Drawer）
- **路由**：`/admin/news/create`
- **存取權限**：ROLE_ADMIN
- **UI 元件**：
  - 頁面標題「新增消息」／返回列表連結
  - 標題輸入（必填，最多 100 字）
  - 類別選擇（單選：公告 / 活動 / 系統，必選）
  - 重要消息 Toggle（勾選後列表加星號，前台置頂顯示）
  - 封面圖片上傳區（可選，拖曳 / 點擊）
  - 內文富文本編輯器（支援標題、粗體、斜體、列表、連結）
  - 排程設定：
    - 發布時間（DateTimePicker，可選，留空 = 立即發布）
    - 下架時間（DateTimePicker，可選）
  - 預覽按鈕（在新分頁開啟前台樣式預覽）
  - 底部操作列：「儲存草稿」、「立即發布」、「取消」

### 頁面 3 — 編輯消息頁面
- **路由**：`/admin/news/{id}/edit`
- **存取權限**：ROLE_ADMIN
- **UI 元件**：
  - 同新增頁面，預填所有現有資料
  - 頂部顯示當前狀態徽章
  - 若為「已發布」狀態，警告文字「儲存後前台內容將立即更新」

### 頁面 4 — 消息詳情預覽頁（僅後台預覽）
- **路由**：`/admin/news/{id}/preview`
- **存取權限**：ROLE_ADMIN
- **UI 元件**：
  - 以前台樣式呈現消息詳情
  - 頂部管理工具列（返回編輯、發布按鈕）

## 使用者情境與測試

### 使用者故事 1 — 管理員建立並立即發布一則活動公告（優先級：P1）

管理員撰寫一則新活動公告，填寫完內容後直接點擊「立即發布」，前台玩家可即時看到此消息。

**此優先級的原因**：消息管理的核心流程，確保營運資訊可及時傳達給玩家。

**獨立測試**：以 Admin 帳號登入，建立一則含標題、類別「活動」和內文的消息，點擊「立即發布」，確認在前台顯示。

**驗收情境**：
1. **在** 消息新增頁面，**當** 管理員填寫標題、選擇類別「活動」、輸入內文，並點擊「立即發布」，**則** 消息狀態為「已發布」，出現在列表頁及前台消息列表頂部。
2. **在** 標題欄位為空，**當** 點擊「立即發布」，**則** 顯示驗證錯誤「標題為必填欄位」，不送出 API。
3. **在** 消息已發布後，**當** 管理員在編輯頁面修改標題並儲存，**則** 前台消息標題立即更新。

---

### 使用者故事 2 — 管理員建立草稿並排程發布（優先級：P1）

管理員提前撰寫節慶活動消息，儲存為草稿，並設定未來時間自動發布，減少當天操作負擔。

**此優先級的原因**：排程功能是消息管理的高頻需求，尤其在節慶活動前。

**獨立測試**：建立一則消息，設定發布時間為「現在 + 5 分鐘」，儲存為草稿，等待確認自動發布。

**驗收情境**：
1. **在** 新增消息頁面，**當** 管理員填寫完整資訊、設定未來發布時間並點擊「儲存草稿」，**則** 消息以「排程中」狀態儲存，列表顯示預計發布時間。
2. **在** 排程時間到達，**當** 後端執行自動發布，**則** 列表頁消息狀態自動更新為「已發布」（需手動重新整理或 WebSocket/polling）。
3. **在** 下架時間設定早於發布時間，**當** 嘗試儲存，**則** 表單驗證錯誤「下架時間必須晚於發布時間」。

---

### 使用者故事 3 — 管理員封存舊消息（優先級：P2）

過期的活動消息不再需要前台顯示，管理員將其封存，從前台消失但後台仍可查詢。

**此優先級的原因**：資料維護功能，保持前台消息列表整潔。

**驗收情境**：
1. **在** 消息為「已發布」狀態，**當** 管理員點擊「封存」，**則** 消息狀態變為「已封存（橘色）」，前台消息列表不再顯示此筆記錄。
2. **在** 列表頁選擇「全部」狀態篩選，**當** 查詢，**則** 已封存消息仍出現在後台列表。

---

### 使用者故事 4 — 管理員標記重要消息（優先級：P2）

管理員將緊急通知標記為「重要消息」，確保前台置頂顯示並有醒目標識。

**驗收情境**：
1. **在** 新增消息時，**當** 勾選「重要消息」並發布，**則** 列表頁顯示黃色星號（⭐），前台消息列表此條目有特殊視覺標識。
2. **在** 篩選列選擇「重要消息」，**當** 查詢，**則** 僅顯示 `isImportant: true` 的消息。

---

### 邊界情況

- 刪除「已發布」狀態的消息前，需先取消發布或封存，否則提示「請先下架消息再刪除」。
- 圖片上傳失敗時，顯示錯誤並保留已填寫的文字內容。
- 富文本編輯器內容為空時，「立即發布」仍可送出（內文非必填）。
- 標題超過 100 字時，即時顯示字數提示「已輸入 X/100 字」，超過後禁止繼續輸入。
- 排程發布後管理員手動點擊「取消排程」，消息應退回「草稿」狀態。

## API 串接規格

### 消息管理

| 動作 | Method | 端點 | 主要 Request 欄位 | 主要 Response 欄位 | 前端 UI 狀態 |
|------|--------|------|------------------|--------------------|-------------|
| 查詢消息列表 | POST | `/api/admin/news/list` | `condition:{category, isImportant, keyword, startDate, endDate}` | `[{id, title, content, category, isImportant, status, imageUrl, publishTime, unpublishTime}]` | loading → 表格渲染 |
| 新增消息 | POST | `/api/admin/news` | `title, content, category, isImportant, imageUrl, publishTime, unpublishTime` | `{id, title, status, ...}` | 按鈕 loading → Toast → 導向列表 |
| 更新消息 | PUT | `/api/admin/news/{id}` | `title, content, category, isImportant, imageUrl, publishTime, unpublishTime` | `{id, title, status, ...}` | 按鈕 loading → Toast |
| 刪除消息 | DELETE | `/api/admin/news/{id}` | — | `{success: true}` | 確認 Dialog → loading → 列表移除 |
| 發布消息 | POST | `/api/admin/news/{id}/publish` | — | `{id, status: "PUBLISHED"}` | 按鈕 loading → 狀態更新 |
| 取消發布 | POST | `/api/admin/news/{id}/unpublish` | — | `{id, status: "DRAFT"}` | 按鈕 loading → 狀態更新 |

## 功能需求（前端 UI）

### 介面需求

- **FR-UI-001**：類別徽章顏色：公告（藍）、活動（紫）、系統（橘）。
- **FR-UI-002**：狀態徽章：草稿（灰）、排程中（藍邊框白底）、已發布（綠）、已封存（橘）。
- **FR-UI-003**：重要消息在列表欄位顯示黃色⭐圖示；非重要則空白。
- **FR-UI-004**：消息列表依「發布時間 DESC」排序，草稿排在已發布消息之後（或提供排序切換）。
- **FR-UI-005**：富文本編輯器至少支援：H2/H3 標題、粗體、斜體、有序／無序列表、超連結插入、圖片插入（URL）。
- **FR-UI-006**：發布時間 DateTimePicker 留空代表立即發布（送出時不帶 `publishTime` 欄位或帶 null）。
- **FR-UI-007**：消息詳情 / 編輯頁面有「返回列表」麵包屑導航。
- **FR-UI-008**：操作確認行為：發布直接執行；刪除需二次確認 Dialog。

### 狀態管理

- **SM-001**：列表載入使用 skeleton loading。
- **SM-002**：新增 / 編輯頁面離開前若有未儲存變更，顯示「有未儲存的變更，確定離開？」提示。
- **SM-003**：發布成功後顯示 Toast「消息已發布」，列表狀態徽章即時更新。
- **SM-004**：儲存草稿成功後顯示 Toast「草稿已儲存」，留在當前編輯頁面。
- **SM-005**：篩選條件自動觸發列表重新查詢（關鍵字 debounce 300ms）。

## API 驗證清單

- **AV-001** ✅：`POST /api/admin/news/list` 支援 `category`、`isImportant`、`keyword`、`startDate`、`endDate` — 滿足前端篩選需求。
- **AV-002** ✅：`category` 枚舉值（`ANNOUNCEMENT`/`EVENT`/`SYSTEM`）明確定義 — 前端可對應中文標籤。
- **AV-003** ⚠️：封存狀態（`ARCHIVED`）— 後端僅說明「states: draft/published/archived」但未提供獨立的封存 API；需確認是透過 `PUT` 更新 status 欄位，還是另有端點。
- **AV-004** ⚠️：`POST /api/admin/news/{id}/unpublish` 的目標狀態 — 已發布消息取消發布後，狀態應為「草稿」還是「已封存」？後端 spec 未明確說明，前端狀態機設計需確認。
- **AV-005** ❌：消息內文的圖片上傳 — 富文本中若包含圖片，需要圖片上傳端點；後端 spec 未提供富文本圖片上傳 API，可能需要使用通用圖片上傳端點或 S3 直傳。
- **AV-006** ⚠️：列表 Response 中的 `content` 欄位 — 列表頁回傳完整 `content` HTML 可能過大；建議確認是否有 `excerpt`（摘要）欄位，或前端截取顯示。
- **AV-007** ✅：`isImportant` 為 boolean — 前端 Toggle 元件對應明確。
- **AV-008** ❌：排程取消功能 — 後端無獨立的「取消排程」API；排程後若要取消，前端應透過 `PUT` 將 `publishTime` 設為 null 來實現，需後端確認此做法有效。

凡例：✅ 已確認一致 | ⚠️ 需要確認 | ❌ 發現缺口或不一致

## 成功標準

### 可量化的成果

- **SC-001**：管理員可在 5 分鐘內完成一則消息的撰寫與發布。
- **SC-002**：消息列表載入時間不超過 2 秒（假設 50 筆以內）。
- **SC-003**：富文本編輯器支援至少 5 種基本格式（標題、粗體、斜體、列表、連結）。
- **SC-004**：排程功能在設定時間後 1 分鐘內自動發布（依後端執行精度）。
- **SC-005**：篩選類別後，列表即時更新（1 秒內），無需手動重新整理。
- **SC-006**：所有操作（新增、編輯、發布、刪除）均有明確成功或失敗的 UI 回饋。
