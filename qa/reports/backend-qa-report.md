# 後端 QA 檢查報表

這份文件要呈現什麼內容：
提供後端 API QA 的主檢查報表，讓執行者知道本次要檢查哪些模組、每個代號代表什麼、成功與失敗如何判定，以及失敗時應該記錄哪些原因。

## 報表目的

本報表聚焦 Spring Boot 後端，優先確認下列高風險模組：

- 會員認證與會員資料
- 商品與獎品管理
- 抽獎、刮刮樂與併發
- 儲值、付款與回呼
- 訂單與出貨
- 後台角色權限
- 稽核與系統日誌

## 測試環境

- API Base URL：`http://localhost:8080/api`
- 專案型態：Spring Boot 後端
- 測試資料來源：`qa/test-data/`
- API 案例來源：`qa/test-cases/api-test-cases.json`
- 人工案例來源：`qa/test-cases/manual-test-cases.csv`

## 代號說明

| 代號 | 說明 |
|------|------|
| P0 | 重大風險。影響金流、扣點、庫存、訂單、權限或資料一致性，通常不可上線 |
| P1 | 核心流程。失敗會影響主要使用者流程 |
| P2 | 一般功能或次要流程 |
| AQA | API QA，後端 API 測試案例 |
| MQA | Manual QA，人工測試案例 |

## 成功與失敗判定規則

### 成功

- 回應 HTTP 狀態碼符合預期
- 回應欄位完整且格式正確
- 資料庫狀態、錢包餘額、庫存、賞品盒、訂單狀態一致
- 權限限制生效，未授權操作被阻擋
- 失敗情境可追蹤，不會留下無法解釋的半成功資料

### 失敗

- 狀態碼錯誤或回應格式不符合規格
- 成功回應但資料未正確落地
- 失敗回應但仍改動餘額、庫存、訂單或獎品狀態
- 權限限制被繞過
- 併發情境產生超賣、重複扣點、重複建立資料
- 付款或訂單異常沒有留下足夠的追蹤資訊

## 失敗原因紀錄表

| case id | 模組 | 結果 | 失敗原因分類 | 詳細原因 | requestId | 是否阻擋上線 |
|---------|------|------|--------------|----------|-----------|--------------|
| 範例：AQA-013 | 抽獎流程 | 失敗 | 併發控制錯誤 | 最後一抽兩位玩家都成功，庫存變成 -1 | 待填 | 是 |
| 範例：AQA-018 | 付款回呼 | 失敗 | 資料一致性錯誤 | callback 成功但查無 order 資料 | 待填 | 是 |

失敗原因分類建議使用：

- 規格不一致
- 權限錯誤
- 資料一致性錯誤
- 併發控制錯誤
- 金流或訂單流程錯誤
- 驗證規則錯誤
- 環境問題
- 待釐清

## 待確認問題

- `刮刮樂商品必須設定免費抽門檻` 是否仍為現行商業規則，或應改為店家選填機制
- `POST /api/order` 與目前程式中的 `/api/order/ship` 是否存在文件與實作差異
- 付款回呼、訂單建立與庫存更新失敗情境是否已有正式 fault injection 測試方式

## 最終結論

本報表可作為後端 QA 的主執行文件。建議先從 P0 與 P1 案例開始，優先確認抽獎、付款回呼、訂單與權限四大區塊，再決定是否可進入下一階段。
