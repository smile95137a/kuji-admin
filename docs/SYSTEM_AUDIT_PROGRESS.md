# 系統巡檢進度

最後更新：2026-05-11

## 目前巡檢策略

只針對「可能不完整、可能不一致、可能不符合產品預期」的模組深入檢查。

巡檢標準固定如下：

1. 後端是否真的有對應能力
2. 後台前端是否有對應頁面、route、API 對接
3. 前台是否會看到衝突結果
4. 權限、狀態、顯示層、防呆是否一致

已確認並已落地：

2. 後台前端 route 已補齊
3. `adminReportService.ts` 已改回一對一對應正確 API

下一步要做：

1. 逐張報表內容審查
2. 與產品預期逐項比對

目前已新增的拍板結論：

1. 推薦碼報表
	- `推薦成功` 以「店家啟用成功」為準，不看店家建立、審核通過、首次上架。
	- 此報表的核心是店薦店招商成效，不是會員拉新報表。

2. 儲值 / 紅利 / 平台營收總覽
	- 視為同一個平台金流模組下的不同視圖。
	- `平台營收總覽` 是高層 KPI。
	- `儲值報表` 看平台流入。
	- `紅利報表` 看平台發放與消耗。
	- 原本殘留的店家視角屬舊設計待收斂。

3. 抽獎結果報表
	- 正式採用「摘要 + 中獎明細」雙層設計。
	- 核心主體必須是實際中獎結果，不再以獎池統計為主。

報表重做順序已收斂為：

1. 推薦碼報表重定義
2. 會員成長報表拆平台視角
3. 儲值 / 紅利報表切平台金流語意
4. 抽獎結果報表改為中獎結果核心
